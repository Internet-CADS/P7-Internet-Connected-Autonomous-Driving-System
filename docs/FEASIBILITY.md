# Phase 1 feasibility

19 November 2026 · Windows, Intel Core i5-12600KF, CPU only

- **Model serving (B1, B2).** At [models commit `64a5264`](https://github.com/Internet-CADS/models/tree/64a52648080ad5d4aa52bfa48ebdcf89356a5241), all 21 selected checkpoint files exist. The report's peak-of-mean calculation confirms frames 1,500,000 (vanilla), 1,600,000 (SA-DQN), and 1,450,000 (WocaR-DQN), seven seeds each. Seed 1 from each group loaded with plain PyTorch outside the models checkout and exactly matched the original inference constructor's Q-values on 32 seeded reset observations. All three chose action 3 (`FASTER`) on the seed-0 reset. The checkpoints contain three linear layers with ReLUs between them, 50→128→128→5, with a single output head. The original inference constructor ran with `auto_LiRPA` absent. Use plain PyTorch and keep the reference comparison as a regression check.
- **Perturbation compatibility (B2, B4).** The standalone simulator probe reproduced the evaluator output exactly for 640 cases (32 observations × four methods × five budgets) with matched random starts. Every repeat matched and every L∞ bound held. In all 512 nonzero-budget cases, at least one output entry exceeded the nominal `[-1, 1]` range. The evaluator projects relative to the original observation, which allows values just beyond the normalized input range. The threat model needs to specify this explicitly because clipping or masking changes the comparison with the repository.
- **Crash-rate probe (B2, B4).** For vanilla checkpoint seed 1, using the same 50 simulator seeds (0–49) in each condition, crash counts were **9/50 clean (18%), 15/50 random noise (30%), 33/50 PGD (66%), 39/50 MinBest (78%) and 37/50 worst-Q (74%)**. All four perturbations used ε = 0.01. All 9,340 observed steps met the budget within 1e-6. RNG uses the episode seed and step index, so the rollouts use a different random stream from the repository's full evaluation. This is a one-checkpoint feasibility probe. The model ranking will be tested across seeds through the service.
- **Performance and runtime (B1, B4).** On Python 3.13.7, CPU PyTorch 2.7.1, highway-env 1.12.1 and Gymnasium 1.4.0, single-observation inference plus argmax took 22.4 µs p50 and 27.6 µs p95 (5,000 calls, one PyTorch thread). The rev3 highway configuration ran at 70.7 steps/s (677 headless `IDLE` steps over 30 seeded episodes, 13.93 ms p50 and 16.28 ms p95; resets excluded). It uses four lanes, 15 other vehicles, a 60-step limit, Kinematics 10 × 5, five actions, 5 Hz simulation and 1 Hz policy. These are in-process measurements on this machine. The original inference constructor, adapter and perturbation function were checked. The full legacy training and certification requirements were outside the tested runtime.
